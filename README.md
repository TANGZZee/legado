# 阅读Archive

> 一个基于 Legado 的个人维护分支，重点优化书架自动整理、内容标签和阅读数据统计。

[![Android](https://img.shields.io/badge/platform-Android-green.svg)](https://www.android.com/)
[![License](https://img.shields.io/badge/license-GPL--3.0-blue.svg)](LICENSE)

## 项目简介

**阅读Archive** 是在开源阅读应用 Legado 基础上的个人功能增强分支。

项目保留原 Legado 的书源、订阅、本地阅读、漫画、音频、主题和高度自定义能力，主要针对日常使用中的三个问题继续优化：

1. 新加入书架的内容需要手动整理；
2. 阅读记录只有基础累计数据，缺少可视化分析；
3. 长期阅读过程中，阅读时段、阅读趋势和统计组件不够完整。

本仓库不是 Legado 官方仓库，也不提供书源内容。书源、订阅源和阅读内容仍由用户自行配置和管理。

## 在原 Legado 基础上完成的功能

### 1. 书架自动分组

新书加入书架时，根据内容类型自动归入对应分组：

- 新增小说、漫画的内置虚拟分组；
- 优先使用用户创建且名称精确为“小说”或“漫画”的自定义分组；
- 没有同名自定义分组时，使用内置类型分组兜底；
- 内置分组与可见的同名自定义分组不会重复显示；
- 只处理新加入书架的书籍，不擅自迁移用户已有书籍。

### 2. 自动内容标签

根据书源分类、书名/文件名和书源名称自动合并内容标签：

- 小说：玄幻、奇幻、武侠、仙侠、都市、历史、科幻、悬疑、言情、穿越、重生、系统等；
- 漫画：热血、冒险、搞笑、恋爱、校园、奇幻、科幻、悬疑、推理、运动、恐怖等；
- 音频：有声小说、儿童、相声、评书、广播剧、播客、音乐、戏曲、新闻、故事等；
- 优先读取书源 `kind`，再结合书名、文件名和书源名补充识别；
- 不覆盖用户已有标签，只做合并；
- 对历史书籍提供一次性合并补标，保留原有标签。

### 3. 阅读统计

在底部“统计”页签和“我的 → 阅读记录”中接入真实数据统计组件：

- 日、周、月、年、总共 5 种统计范围；
- 阅读时间；
- 阅读天数；
- 累计读过的书籍；
- 读完书籍；
- 在读书籍；
- 阅读字数；
- 阅读速度；
- 记录笔记数量。

统计数据不是静态展示：

- 每日阅读时长和字数写入 Room 数据库；
- 按日按书记录阅读时长、字数和完成状态；
- “记录笔记”按统计范围内新增书签数量计算；
- 统计逻辑抽为纯函数并配有单元测试；
- 顶部日期、月份、年份选择与统计卡片时间范围联动。

### 4. 阅读趋势

新增阅读趋势组件，支持：

- 阅读时间、阅读字数、阅读速度三种指标切换；
- 柱状图、折线图切换；
- 图表颜色跟随应用主题色；
- 指标卡显示与上一统计周期的涨跌趋势；
- 日视图按小时、周视图按星期、月视图按等间隔日期、年视图按月份、总视图按年份展示横轴。

日视图采用真实小时记录，不再把当天累计时长错误堆到某一个时间点。

### 5. 阅读时段与时段占比

新增两个统计组件：

- **阅读时段**：展示 24 个小时区间的阅读柱状图，并显示最常阅读时间、最常时段、平均开始时间和夜间占比；
- **时段占比**：展示凌晨、上午、下午、晚上的阅读时长比例和明细。

时间区间定义：

- 凌晨：00:00–05:59；
- 上午：06:00–11:59；
- 下午：12:00–17:59；
- 晚上：18:00–23:59。

小时图采用“区间柱 + 边界刻度”的设计：

- 第 1 根柱子表示 `00:00–01:00`；
- 第 2 根柱子表示 `01:00–02:00`；
- 第 5 根柱子表示 `04:00–05:00`；
- 横轴 `0、4、8、12、16、20、24` 表示时间边界；
- `0` 和 `24` 是同一天的左右边界，不是两条重复数据；
- 这样 24 根柱子完整覆盖 `00:00–24:00`。

### 6. 统计组件管理与阅读体验修复

- 统计页组件可开关和调整顺序；
- 修复组件开关因整行点击与 Switch 双重触发而无法保存的问题；
- 修复组件配置弹窗底部按钮在手机上被挤出的问题；
- 修复正文排版高度交替跳变和旧排版任务覆盖新章节的问题；
- 版本号与上游对应版本保持一致，避免无意义的更新提示。

## 数据与兼容说明

- 新增按小时阅读记录表，用于日趋势和阅读时段分析；
- 新版本之前产生的历史阅读总时长没有小时粒度，因此旧数据可能只能显示累计统计，无法还原到具体小时；
- 从支持小时记录的版本开始，新的阅读行为会按“日期 + 小时”真实累计；
- 数据库迁移由应用自动处理，不需要用户手动修改数据库。

## 构建环境

本项目当前验证环境如下，依赖统一放在 D 盘：

```text
JDK:             D:\DevTools\jdk-17.0.20+8
Gradle:          D:\DevTools\gradle-8.14.4
Gradle 用户目录: D:\DevTools\Gradle
Android SDK:     D:\AndroidSdk
项目目录:        D:\legado
```

Windows PowerShell 环境变量：

```powershell
$env:JAVA_HOME='D:\DevTools\jdk-17.0.20+8'
$env:GRADLE_USER_HOME='D:\DevTools\Gradle'
$env:ANDROID_HOME='D:\AndroidSdk'
$env:ANDROID_SDK_ROOT='D:\AndroidSdk'
```

构建命令：

```powershell
# x86_64 模拟器
.\gradlew.bat assembleAppDebug -Pabi=x86_64 --console=plain

# arm64-v8a 手机
.\gradlew.bat assembleAppDebug -Pabi=arm64-v8a --console=plain

# 阅读统计单元测试
.\gradlew.bat :app:testAppDebugUnitTest --tests "io.legado.app.ui.about.ReadRecordStatisticsTest"
```

本地验证过的 APK 输出目录：

```text
app\build\outputs\apk\app\debug\
```

## 开发约定

- 代码修改统一在 `D:\legado` 完成；
- 构建前先读取 `E:\阅读优化项目\AGENTS.md` 和 `.agent-handoff` 交接文件；
- Gradle/KSP 任务必须串行执行，避免并行任务损坏 KSP 缓存；
- 新功能需要经过单元测试、对应 ABI 构建和设备验证；
- 模拟器使用 `emulator-5554`，真机使用 `7784ace4`；
- 与上游同步：

```bash
git fetch upstream
git merge upstream/main
```
